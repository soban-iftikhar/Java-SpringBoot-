# Object Class and the `final` Keyword: Theoretical Notes

## 1. The `final` Keyword
The `final` keyword is used to restrict the user. It is the ultimate "lock" in Java, and it operates at three different levels:

1. **Variables (`final int x = 10;`)** 
   - Creating a final variable turns it into a **Constant**. Once a value is assigned, it can never be changed or reassigned. 
2. **Methods (`public final void execute()`)**
   - Locking a method prevents any Child class from **overriding** it. You use this when a piece of logic is critical to your system's architecture and you do not trust subclasses to modify it.
3. **Classes (`final class SecuritySystem`)**
   - Locking an entire class completely prevents **Inheritance**. No other class is allowed to `extends` a final class. (For example, the Java `String` class is final to ensure absolute security and immutability).

## 2. The `Object` Class (The Cosmic Mother)
In Java, **every single class** you ever create implicitly extends the `java.lang.Object` class. It sits at the very top of the Java inheritance tree. Because of this, every object inherits several crucial built-in methods.

### The Big Three Overrides

#### 1. `toString()`
By default, if you print an object (`System.out.println(myLaptop)`), the Object class runs its default `toString()` method, which outputs the class name combined with a gibberish memory address hash (e.g., `Laptop@15db9742`).
- **Why Override?** You override `toString()` so that when you print the object, it returns a human-readable string containing the actual data inside the object (e.g., `Laptop [Brand: Apple, Serial: 9999]`).

#### 2. `equals(Object obj)`
By default, the Object class's `.equals()` method functions exactly like the `==` operator. It strictly checks if two references point to the exact same physical memory location on the Heap.
- **Why Override?** If you have two different Laptop objects in memory, but they both have the same serial number, you probably want Java to consider them "equal." You override `.equals()` to write your own custom logic comparing their internal data.

#### 3. `hashCode()`
A HashCode is a unique integer value generated by a hashing algorithm, used by data structures like `HashMap` and `HashSet` to store and retrieve objects with blazing speed.
- **The Golden Contract:** If you override `.equals()`, you **MUST** override `.hashCode()`. The strict rule of Java is: If two objects are considered equal according to your `.equals()` method, they **must** return the exact same integer when `.hashCode()` is called on them. If you break this contract, data structures like `HashMap` will malfunction and lose your data!
